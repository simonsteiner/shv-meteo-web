# Web architecture

The web version reproduces the native mobile application in the browser: static Astro pages, one per tab, each driven by its own TypeScript page script:

- **Pages** (`src/pages/<tab>/index.astro`, built by Astro): each wraps [src/layouts/Base.astro](../../src/layouts/Base.astro) (head, the inline theme script, the header and bottom nav, the `view` slot, the map's bottom sheet) and sets `<body data-view>`; four tabs: map, weather, forecast, safety (`/profile/` redirects to `/map/`).
- **Shell**: the header and bottom nav are `.astro` in [src/components/shell/](../../src/components/shell/), with real `<a href="/<tab>/">` links and the current tab marked `aria-current="page"` at build time, worded in German until the saved language is applied. [src/scripts/shell/shell.ts](../../src/scripts/shell/shell.ts), loaded by `Base.astro` before the page's script, installs the global `error` and `unhandledrejection` loggers (`errors.ts`), reloads a page restored from the back/forward cache, and wires the header (`header.ts`): the language and theme switches, the GPS button (off the map it hands `?locate` to the map) and the Foehn pill (`foehn-pill.ts`).
- **State**: `store` in [src/scripts/state.ts](../../src/scripts/state.ts) is the page's one [`AppState`](../../src/scripts/app-state.ts); it sets the document's theme and language before any page listener runs. `store.setTab` navigates to `/<tab>/`; selections handed to the map travel in its URL (`?site`, `?station`, `?webcam`, `?locate`, each with an optional `&z=<zoom>`; [src/scripts/handoff.ts](../../src/scripts/handoff.ts)). `store` persists language, theme, map settings, vario rate and logbook to `localStorage` (`shv_*` keys, [src/scripts/settings.ts](../../src/scripts/settings.ts)) and the checklist to `sessionStorage`.
- **Tab pages**: the safety page (checklist, emergency numbers, DABS, variometer, logbook) is `.astro` markup in [src/components/safety/](../../src/components/safety/), filled in the `view` slot of `Base.astro`, with its behaviour in [src/scripts/safety/](../../src/scripts/safety/) (`page.ts` attaches the handlers; the rest are pure, tested modules). The weather page (station pairs, live stations, webcams) follows it in [src/components/weather/](../../src/components/weather/) and [src/scripts/weather/](../../src/scripts/weather/), with its charts in [src/scripts/charts/](../../src/scripts/charts/) and its tab and pair in the URL (`/weather/?tab=webcams&pair=GVE_GUT`). The map page is the same: [src/components/map/](../../src/components/map/) and [src/scripts/maps/](../../src/scripts/maps/) (`page.ts` applies to Leaflet and the DOM what `session.ts` answers: what loaded or failed, which handed-over selection to take once, what a store change redraws; the Leaflet layers are in `layer-*.ts` and `view.ts`, with pure modules for each layer's look), and its page script renders the bottom sheet from [src/scripts/sheet/](../../src/scripts/sheet/), one builder per selection (site, station, webcam, obstacle). Their words come from the dictionaries through `data-t` attributes ([src/scripts/i18n/text.ts](../../src/scripts/i18n/text.ts)), so the language switch still works without a reload, and every stored or upstream value in an HTML string goes through `escapeHtml` ([src/scripts/escape.ts](../../src/scripts/escape.ts)).
- **Forecast pages**: `/forecast/` (text forecasts) and `/forecast/{outlooks,emagram,isobaren}/` share [src/components/forecast/ForecastPage.astro](../../src/components/forecast/ForecastPage.astro); each section's component brings its own script from [src/scripts/forecast/](../../src/scripts/forecast/). Upstream's forecast HTML goes through `sanitizeForecastHtml` (`sanitize.ts`), which keeps only the elements the forecasts use. Deep links: `?cat=` and `?region=` on the text, `?type=` on the outlooks, `?station=` on the emagram.
- **Content Security Policy**: [src/scripts/access/csp.ts](../../src/scripts/access/csp.ts), an integration in `astro.config.mjs`, writes a meta CSP right after `<meta charset>` in every built page: scripts only from the site plus the hash of each inline script (the theme script), images from the site or any `https:` origin, `fetch` only from the site and the two upstream CDNs `ShvApi` reads directly (`static-prod.ubmeteo.io`, `shv-app-static-prod.ubmeteo.io`), inline styles allowed for Leaflet and Chart.js. [public/_headers](../../public/_headers) adds `frame-ancestors 'none'` (ignored in a meta tag), `Referrer-Policy` and `nosniff`.
- **Data client**: [src/scripts/api.ts](../../src/scripts/api.ts) (`ShvApi`, typed against [src/scripts/types.ts](../../src/scripts/types.ts)) is the only module that calls `fetch`; it caches the GIS datasets in memory.
- **Translations**: [src/scripts/i18n/](../../src/scripts/i18n/) holds `de`, `fr`, `it` and `en` (the map page's strings in `map/`, for the token budget), read through `store.t`. The other languages are typed as German's shape, and `dictionaries.test.ts` checks that all four have the same keys.
- **API** ([functions/api/](../../functions/api/), Cloudflare Pages Functions): the `/api/*` routes in [data-queries.md](data-queries.md), one-line adapters over [src/scripts/upstream/](../../src/scripts/upstream/). Shared shapes, and the Functions' `Context` type, are in [src/scripts/types.ts](../../src/scripts/types.ts).
- **Dev launcher**: [scripts/dev.ts](../../scripts/dev.ts) runs `wrangler pages dev public` on `8788`, which compiles `functions/` without a build, and `astro dev` on `4321`, which proxies `/api` to it ([astro.config.mjs](../../astro.config.mjs)).

## Member login

There is none. The copy-paste PKCE login against SHV Keycloak reused the official Android app's public client; it went with Express (PR9) and the Profile tab (PR13). The header links to the SHV member portal, and `purgeLegacyAuth` clears the session id and profile old versions stored. How the official app's login works is in [reference/shv-native-auth.md](../reference/shv-native-auth.md); the design to use if login returns is in the [migration plan](../plan/2026-11-23-astro-cloudflare/target.md#auth-deferred).
